# LDB Lab — AI Command Terminal

A standalone, terminal-styled web interface with **LDB Lab ASCII art on startup**, powered by **WebLLM**. Run Qwen and Llama in your browser using WebGPU. No API key, backend, Node build, or GitHub Actions are needed.

## Deploy to GitHub Pages

### Option A — New repo (recommended)
1. Create a **public** GitHub repository named `ldb-lab-terminal`.
2. Upload `index.html` to the **root** of the repository.
3. Open **Settings → Pages**. Under **Build and deployment**, choose **Deploy from a branch**, **main**, and **/(root)**. Save.
4. Your terminal will appear at `https://YOUR-USERNAME.github.io/ldb-lab-terminal/` once Pages publishes it.

### Option B — Existing `lab` repo
1. Create a folder `terminal` in the `lab` repo.
2. Put `index.html` inside as `terminal/index.html`.
3. With GitHub Pages already enabled, visit the Pages site at `/lab/terminal/` (exact domain/path depends on the repo's Pages settings).

## How to use

1. Open the deployed site using **Chrome or Edge on a desktop** with a working GPU/WebGPU adapter.
2. Select a model using the dropdown (start with **Qwen 3 0.6B** or **Qwen 2.5 0.5B**).
3. Click **LOAD MODEL**. The first download may take substantial time and hundreds of megabytes or more.
4. Type a prompt and press Enter. Responses stream into the terminal.

Commands: `/help`, `/models`, `/model qwen`, `/load`, `/status`, `/system <text>`, `/clear`, `/reset`, `/export`, `/stop`, `/about`. Up/down arrows navigate command history, Ctrl+L clears.

## Notes and limitations

- **Not a system shell:** terminal commands manage the AI application. This app does **not** run bash commands, install software, or execute code on GitHub servers.
- **Actually runs inference:** replies are generated by the selected local AI model, not canned text.
- **No secret credentials:** no API keys are required or embedded.
- **Browser privacy:** prompts are processed locally after the model assets are downloaded. The page fetches code/assets from jsDelivr, GitHub/Hugging Face, and MLC model hosts. The app does not deliberately upload prompts to a server.
- **Temporary chat history:** messages are in memory and disappear upon reloading the page. Use `/export` before closing if you want a JSON copy.
- **Hardware requirements:** WebGPU and adequate GPU memory are mandatory. Small models are recommended on laptops; larger models may fail on constrained devices. Browser compatibility varies.
- **Model catalog:** the app uses the model IDs actually provided by the pinned WebLLM 0.2.86 library, rather than constructing model URLs manually. If a preferred model is absent, it will not be shown.
- **Dependency:** loads `@mlc-ai/web-llm@0.2.86` as a JavaScript module from jsDelivr. Internet is required on first startup and for model downloads. Dependency/CDN changes could affect later operation.
- **Model licensing:** check the license/usage terms of each model separately, especially Llama.
- **Not yet repo-integrated:** this is a standalone implementation, not an extraction of verified files from your `lab` repo.

## Extending

The `preferred` array in `index.html` controls which models appear, provided the chosen ID is present in WebLLM's prebuilt catalog. You can add more supported model IDs there. For cloud models in the future, use a **secure server-side proxy**; never commit API keys into public HTML/JavaScript.
